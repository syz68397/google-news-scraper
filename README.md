## ScraperAPI是什么，适合谁用

简单说，ScraperAPI是一个代理+反检测+自动重试的中间层。你把目标URL通过它的API发出去，它帮你处理IP轮换、浏览器指纹、验证码识别这些脏活。返回的就是干净的HTML或者JSON。

它不是爬虫框架，不替你写解析逻辑。你还是需要自己处理数据提取和存储。但它解决的是采集过程中最头疼的那个环节：怎么让请求不被目标网站拦截。

适合的人群很明确：

- 需要采集Google搜索结果、Google新闻、Google Shopping等结构化数据的开发者
- 采集量在每月几万到几百万次请求之间
- 不想自己维护代理池和反检测基础设施
- 项目对稳定性有要求，不能接受"今天能跑明天就挂"

如果你只是偶尔抓几个页面，免费试用的5000次请求够你验证流程了。

## 拿它采集Google新闻数据的实际流程

ScraperAPI有一个专门的Google搜索结构化端点，叫Google Search API。你传入搜索关键词，指定搜索类型为"news"，它直接返回JSON格式的结构化结果，不需要你自己解析HTML。

我的典型调用方式：

```python
import requests

params = {
    "api_key": "你的API密钥",
    "query": "人工智能 医疗",
    "search_type": "news",
    "country": "cn",
    "language": "zh-cn
}

response = requests.get("https://api.scraperapi.com/structured/google/news", params=params)
data = response.json()
```

返回的JSON里包含新闻标题、来源媒体、发布时间、链接、摘要片段。省去了写XPath或CSS选择器的时间。

实际跑下来几个观察：

- 响应时间通常在3到8秒之间，偶尔会到12秒
- 设置country和language参数后，返回结果的地域相关性明显提升
- 每页默认返回10条，可以通过翻页参数获取更多

## 常见问题

### Q: ScraperAPI采集Google新闻会被封号吗？

不会封你的Google账号，因为请求根本不经过你的账号。ScraperAPI用的是它自己的代理IP池去访问Google，你的身份对Google是不可见的。我跑了半年，没有任何账号层面的风险。

### Q: 返回的新闻数据是实时的吗？

基本是实时的。我对比过同一关键词在浏览器里搜和通过API搜的结果，时效性差异通常在几分钟以内。但如果你需要秒级实时，任何API方案都做不到，因为请求本身就有几秒延迟。

### Q: 每月100,000 credits够采集多少条新闻？

如果用结构化端点，每次请求消耗5 credits，每次返回约10条新闻。所以100,000 credits大约能采集200,000条新闻数据。如果你每天监控50个关键词，每个关键词取前30条，一个月下来大概需要45,000 credits。Hobby套餐绑有余。

### Q: 支持采集Google新闻的全文内容吗？

ScraperAPI的Google News端点返回的是搜索结果页的数据（标题、摘要、链接、来源），不是新闻全文。如果你需要全文，得拿到链接后再单独请求各新闻源网站，这部分每次消耗1-10 credits不等，取决于目标站的反爬强度。

### Q: 和直接用Google News RSS相比有什么优势？

Google News的RSS feed限制很多：只能按大类订阅，不支持复杂查询，返回条数有限，而且Google这几年一直在收紧RSS的覆盖范围。API方式支持精确关键词、地域筛选、时间范围，灵活度完全不在一个级别。

### Q: 采集频率有限制吗？

没有硬性的频率限制，但受并发数约束。Hobby套餐20并发意味着同一时刻最多20个请求在跑。如果你的任务是每小时采集一次，20并发完全够用；如果是每分钟大批量采集，就需要更高套餐的并发额度。

### Q: 数据返回格式是什么？

结构化端点返回标准JSON，字段包括title、link、source、date、snippet等。普通端点返回原始HTML，需要自己解析。对于Google新闻采集，强烈建议用结构化端点，省心太多。
